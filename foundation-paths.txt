# 判定の基盤（シミュレーター、ペースの指標の定義、指標を目標値と比べるテストの枠組み）に当たるパスの一覧。
# AGENTS.md「保護範囲」節の「判定の基盤」に当たり、変更は同節の手順（独立判断と、理由を書いた単独の commit）による。
# 保護範囲の変更を検出する hook とスクリプトが読む。
#
# 書式:
# - 1 行に 1 つ、リポジトリのルートからの相対パスのパターンを書く。空行と `#` で始まる行は読まない。
# - パターンは POSIX sh の `case` のパターンとして照合する。`*` は `/` を含む任意の文字列に一致する。
# - `!` で始まる行は除外。パスは、除外でないパターンのどれかに一致し、除外のパターンのどれにも一致しないとき基盤に
#   当たる。行の順序は結果を変えない。

# シミュレーター（ボット、時間の進め方、遊ばせる組、CLI）と、ペースの指標の測り方（src/sim/pace-settings.json）、
# 目標値との比較とそれらのテスト。
# ゲームをシミュレーターの形に合わせる実装（src/sim/minimal-game.ts）とそのテストも含める。シミュレーターはこの実装を
# 通してしかゲームを見ないため、ここで advance を水増しする、未解放の要素を解放済みとして返す、ゲームの仕組みを
# 渡さないといった変更は、ゲームを変えずにペースの判定を通せる。実装が core の関数と購入の規則をそのまま使うことを
# 確かめるテストを基盤に置く案は採らない。そのテストも core の関数の名前と購入の種類を知る必要があり、ゲームの購入を
# 足すたびに書き換わるため、結局は基盤の変更になる。実装は薄く、ゲームの購入を足すときに独立した判断を受ければ足りる。
src/sim/*

# 指標の定義と、設計記録の書式。
docs/design/README.md

# テストの設定。ペースの指標のテストが遊ばせる組（速い組・全組）を選び、テストの共通の検査を定める。

# ペースの指標のテストを commit ごとに回す git hook。外すと、速い組での判定を経ずに commit できる。
lefthook.yml

# 目標値のファイル（docs/design/*.targets.json）と、ゲームごとの設計記録（docs/design/ のほかのファイル）は、
# 数値設計で編集するため含めない。
#
# ペースの指標のテストを呼ぶ package.json の scripts（test・test:pace:full）は、package.json にゲームの依存も
# 書くため、ファイル単位のこの一覧には含めない。scripts の変更は、これから作る取り込み前の検査が、検査の設定として
# package.json の scripts の差分から検出する。その検査ができるまでは、AGENTS.md「保護範囲」の手順だけが守る。
