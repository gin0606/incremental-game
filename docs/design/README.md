# 設計記録

ゲームの数値の伸び方、報酬の間隔、見た目と演出を決めた根拠と、ペースの目標値を残す。書き方の方針は AGENTS.md の「設計と根拠」節による。

## ファイル

- `<対象>.md`: 設計記録。対象はゲーム全体か、その一部（`minimal-game.md` など）。
- `<対象>.targets.json`: その対象のペースの目標値。ペースの指標のテスト（`src/sim/pace.slow.test.ts`）が読み、形は `src/sim/pace-targets.ts` が検査する。

目標値を変える commit は、ゲームの変更とは別にし、変更の根拠を設計記録に書く。

指標をどう測るか（遊ぶ時間、刻み幅、記録の間隔、測るボットの規則、壁の区間と速度、選択の重みで比べる規則、放置の局面・長さ・離れる時間）は、目標値のファイルではなく `src/sim/pace-settings.json` に置く。判定の基盤に含め、変えるときは AGENTS.md「保護範囲」の手順による。目標値の変更として測り方を変えられると、たとえば遊ぶ時間を縮めて終盤を測らないようにできるため。目標値のファイルにこれらの項目を書くと、読み込みで失敗する。

## 設計記録の書式

設計記録は次の節で書く。決めたことごとに節を繰り返してよい。

1. **目的**: 何を決めるための記録か。
2. **出典**: 書誌情報（著者、題名、媒体、年、URL）と該当箇所（節、ページ、スライドの番号）。根拠の種類を「査読論文」「開発者の公開講演・資料」「それ以外」のどれかで書く。原典を読めず、要旨などだけを読んだときは、読んだ範囲をそのまま書く。
3. **原典の主張**: 原典が言っていること。引用は原文のまま書き、訳や要約と区別する。
4. **導いた仮説**: 原典から導いた設計の仮説。文献から得られるのは主に定性的な原則で、具体的な数値は仮説として扱う。
5. **目標値**: 仮説を目標値のファイルのどの項目に、どの値で置いたか。
6. **検証結果**: 確かめた日付、コマンド、ボットの組、刻み幅、測った値、合否。
7. **限界**: 確かめていないこと、指標で捉えられないこと。

## ペースの指標

指標は `src/sim` で、シミュレーターにボットを遊ばせた時系列から求める。生産量は常用対数（桁）で扱う。時間はすべて秒。測り方（`src/sim/pace-settings.json`）と目標値のファイルの項目名を括弧で示す。

### 遊ばせる組

- 速い組（`fastSet`）: commit ごとの検査（`pnpm run test`）で回す。
- 全組（`fullSet`）: 取り込み前に `pnpm run test:pace:full` で回す。環境変数 `PACE_SET=full` で選ぶ。

組の中身は `src/sim/sets.ts` にある。遊ぶ時間（`duration`）、刻み幅（`step`）、記録の間隔（`sampleEvery`）は測り方で決める。

### 遊んだ結果の指標

妥当なボット（`reasonable` の購入規則で、常に開いているもの）で測る。妥当なボットのどれか 1 つでも帯を外れるか、比べる値が無ければ（節目の比を求める組が無い、など）失敗にし、どのボットで測ったかを結果に出す。

- **節目到達時間と、その比**（`milestones`）: 生産量が `levels` の各桁に初めて達した時刻と、続けて達した節目どうしの時刻の比（後 / 前）。どの節目にも遊ぶ時間のうちに達することも確かめる。時刻は時系列の記録（記録の間隔ごとの記録と、ボットの購入などの出来事）で測るため、記録の時点の生産量で判定するため、ゲームの中の自動購入で記録の間に達した節目は、その節目以上の生産量の最初の記録の時刻になる。
- **対数成長速度とその変動**（`growth`）: 区切り `bounds` の区間ごとに、1 時間あたりに生産量が伸びた桁数（`speed`）と、隣り合う区間の速度の比（`change`）。
- **購入間隔**（`purchases`）: ボットが買った時刻（同じ時刻の購入はまとめる）の間隔の中央値と最長。ゲームの中で自動で起きた購入は含まない。
- **新要素の密度と空白**（`novelty`）: 1 日あたりに解放された要素の数と、解放の時刻の間隔（時刻 0 から最初の解放まで、最後の解放から遊ぶ時間の終わりまでを含む）の最長。最初から解放されている要素は、どちらにも数えない。
- **壁**（`walls`）: 始まりを `sampleEvery` ごとにずらした長さ `window` の区間のうち、速度が `below` を下回る（または測れない）区間が続いた範囲の最長（最初の区間の始まりから最後の区間の終わりまで）。
- **選択の重み**（`choice`）: 最良とみなす規則（`best`）のボットが、選び方を制限した規則（`restricted`）のボットより生産量で先行した最大の桁数。`sampleEvery` ごとの時刻で比べる。Jaffe の restricted play（制限した戦略と制限しない戦略の成績の差で、その選択の影響を測る）に倣う。差が小さすぎれば選ぶ意味が薄く、大きすぎれば最良の選び方を知らないプレイヤーが置いていかれる。

生産量が 0 の時期の常用対数は `-Infinity` とし、伸びや先行の桁数は、両端が同じ有限の値か、どちらも生産量 0 なら 0 とみなす。対数が number を超える生産量どうしでは伸びを測れず、帯の外になる。

### 放置の指標

妥当な規則ごとに、`idle.phases` の各時刻を局面の始まりとして測る。局面の始まりの状態は、その規則の常に開いているボットがその時刻まで遊んだ状態。組に `every` の予定（一定の間隔でだけ開く）のボットがいる規則だけを測る。

- **効率**: 局面の始まりから `idle.window` 秒遊ばせたとき、間隔 Δ ごとにしか開かないボットが、常に開いているボットの何割を生産したか。生産は、記録の生産量が次の記録まで続いたとみなした積分。
- **放置の許容間隔**: 組の間隔を短い順に見て、それ以下の間隔すべての効率が `idle.efficiency` 以上である最大の間隔。最も短い間隔で届かなければ 0。
- **戻ったときの報酬曲線**: 局面の始まりから `idle.away` 秒それぞれ何もせずに離れ、戻った直後にその規則で買えるだけ買った後の生産量の桁。

### 比べ方

隣り合う組を比べる項目（目標値の `milestones.levels`・`growth.bounds`、測り方の `idle.phases`・`idle.away`）には 2 つ以上の値を、目標値の `idle.reachBy` には測り方の最後の局面以下の時刻を書く。そうでないと、比べる組が無く検査が何もしないまま通るため、読み込む時点で失敗にする。

- **帯**: 値が目標値の範囲（`min`〜`max`。省いた側は制限しない）にあるか。端の値は範囲に含める。
- **傾向**:
  - 放置の許容間隔が、局面が進むにつれて縮まない。
  - `idle.reachBy` 秒以降の局面では、放置の許容間隔が `idle.reach` 秒以上。
  - 戻ったときの報酬が頭打ちにならない: 最も長く離れたときの報酬が、ほかのどの離れた時間のときより大きい。短い時間どうしで同じなのは、次の購入に届かないためで、問題にしない。
- **不変条件**（不在を罰しない）:
  - 長く離れたほうが生産量が下がらず、生産量が変わらなければ、資源が生産量 × 延びた時間以上に増える。
  - オフラインの一括計算とオンラインの放置が一致する: 離れた時間を一度に進めた結果と、7 回に分けて進めた結果の生産量と資源が、相対誤差 1e-6 の範囲で一致する。資源は購入の直後に 0 近くまで減るため、離れた間の生産量の目安（生産量 × 離れた時間）を足して比べる。
  - 長く離れたほうが、短く離れたとき以上の生産量で戻れる（報酬曲線が下がらない。常用対数で 1e-6 までの低下は許す）。
- **刻み幅の守り**: 指標を測り方の刻み幅と、その 7 倍の刻み幅の両方で測り、測った値（比など、ほかの値から求める値を除く）が相対誤差 1e-3 を超えて違えば失敗にする。有限でない値（未到達、NaN、±Infinity）は同じ値どうしだけを一致とみなす。シミュレーターの結果は、購入なしに生産量や資源が変わるゲーム（自動購入、時間で伸びる生産量、時限で切れる効果など）では刻み幅に左右されうる（`src/sim/simulate.ts` の `Settings.step`）。この守りが失敗したら、指標を目標値と比べる前に、その制限への対処を決める。2 つの刻み幅のどちらでも同じように見逃す違いは捉えられない。

## 指標が保証しないこと

指標は、ボットが決まった規則で遊んだときのゲームの数値の振る舞いを測るもので、実際のプレイヤーが楽しいか、気持ちよく感じるかは保証しない。プレイヤーのいない指標は、ゲームがどう動くかを調べる道具で、対象のプレイヤーが楽しむかどうかはプレイヤーで確かめるしかない（Nelson "Game Metrics Without Players", 2011）。ボットは、実際のプレイヤーの判断や、画面・演出の受け取り方を再現しない。
